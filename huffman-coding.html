Huffman Coding

Frequent characters get short codes, rare ones get long codes — built by repeatedly merging the two least-frequent nodes into a tree. Watch the compression tree grow, then see the encoded bits.

How it works

Regular text uses a fixed number of bits per character (8 for ASCII), no matter how common that character is. Huffman coding instead gives frequent characters shorter codes and rare characters longer ones, which shrinks the total size — the same idea as Morse code giving "E" a single dot because it's the most common letter.

Building the tree: start with one leaf node per character, each weighted by its frequency. Repeatedly take the two lowest-weight nodes and merge them under a new parent node (weight = sum of the two). Keep merging until only one node — the root — remains.

Each character's code is the path from the root to its leaf, reading left-branches as 0 and right-branches as 1. Because every character sits at a leaf (never partway down a path to another leaf), no code is ever a prefix of another — which is exactly what lets the encoded bits be decoded unambiguously, one character at a time, with no separators needed.
