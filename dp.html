dynamic-programming

DP solves a big problem by filling in a table of smaller subproblems once each, then reusing those answers instead of recomputing them. Watch the table fill in, cell by cell.

how it works

DP applies when a problem has two properties: overlapping subproblems (the same smaller calculation would otherwise get repeated many times — see the plain recursion on the recursion page) and an optimal substructure (the best answer to the big problem can be built directly from the best answers to smaller versions of it). Instead of recomputing, each subproblem's answer gets stored in a table exactly once, and every later cell just looks up what it needs rather than recursing again.

Fibonacci: each cell is just the sum of the two before it — dp[i] = dp[i-1] + dp[i-2] — filled left to right starting from the two base cases.

0/1 knapsack: each cell dp[i][c] answers "best value using only the first i items, with capacity c." For each new item, the cell takes the better of two choices: skip the item (carry forward dp[i-1][c]), or take it (its value plus whatever capacity remains: dp[i-1][c-weight] + value) — but only if it fits.

Edit distance: each cell dp[i][j] is the fewest single-character edits (insert, delete, replace) to turn the first i letters of one word into the first j letters of the other. If the current letters already match, the cost is free — just copy the diagonal cell. Otherwise it's 1 plus the cheapest of the three neighboring cells, since a mismatch always costs exactly one edit however it's resolved.

In every case, the table only needs to be filled once, in an order where each cell's dependencies are already computed — that single pass is what makes DP fast.
