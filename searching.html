Searching

Linear search checks every box in order — O(n). Binary search only works on a sorted array, but halves the search space each step — O(log n). Same array, same target, run both.

How it works

Linear search has no shortcut: it looks at index 0, then 1, then 2, comparing each value to the target, until it finds a match or runs off the end. That's why worst case takes n comparisons for an array of n items — it has no way to know where the target might be, so it can't skip anything.

Binary search only works because the array is sorted first. It looks at the middle element: if that's the target, done. If the target is smaller, the entire right half can be thrown away — nothing sorted below the middle could contain it. If it's larger, the left half is thrown away. Each comparison cuts the remaining range in half, which is why it takes about log₂(n) comparisons instead of n — for 1,000 items, that's ~10 steps instead of up to 1,000.

The trade: binary search needs sorted data up front (sorting itself costs O(n log n)), so it only pays off when you'll search the same data many times.

function binarySearch(array, target):
    low <- 0                          // left edge of the range still worth checking
    high <- length(array) - 1         // right edge of the range still worth checking

    while low <= high:                        // keep going while a range remains
        mid <- floor((low + high) / 2)         // pick the midpoint of the range
        if array[mid] == target:               // found it
            return mid
        else if array[mid] < target:           // target must be to the right
            low <- mid + 1                      // discard the left half, including mid
        else:                                  // target must be to the left
            high <- mid - 1                     // discard the right half, including mid

    return -1  // range shrank to nothing: target isn't in the array

function binarySearch(arr, target) {
  let low = 0, high = arr.length - 1;   // the range of indices still worth checking

  while (low <= high) {                       // keep going while a range remains
    const mid = Math.floor((low + high) / 2);  // midpoint of the current range
    if (arr[mid] === target) return mid;        // found it
    else if (arr[mid] < target) low = mid + 1;  // target is to the right: drop left half
    else high = mid - 1;                        // target is to the left: drop right half
  }

  return -1; // range shrank to nothing: target isn't in the array
}
static int binarySearch(int[] arr, int target) {
    int low = 0, high = arr.length - 1;  // the range of indices still worth checking

    while (low <= high) {                          // keep going while a range remains
        int mid = low + (high - low) / 2;           // avoids overflow vs (low+high)/2
        if (arr[mid] == target) return mid;          // found it
        else if (arr[mid] < target) low = mid + 1;   // target is to the right
        else high = mid - 1;                         // target is to the left
    }

    return -1; // range shrank to nothing: target isn't in the array
}

speed

linear search — O(n)

Steps through the array left to right until it finds the target or runs out of boxes.

binary search — O(log n)

Array is sorted first. Each step checks the middle of the remaining range and throws away the half that can't contain the target.
