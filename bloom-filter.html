Bloom Filter

A fixed-size bit array that answers "have I seen this key before?" without storing any keys at all. Insert a few, then check one — watch how false positives can sneak in.

How it works

A Bloom filter answers "have I possibly seen this before?" using a fixed-size bit array and no stored keys at all — which is what makes it so memory-efficient. It trades certainty for space: it can say "definitely not present," but only ever "maybe present."

Inserting a key runs it through several different hash functions, each producing a bit position, and sets all of those bits to 1. Checking a key runs the same hash functions and checks whether every one of those positions is already 1.

If even one of those bits is 0, the key was definitely never inserted — no false negatives are possible. But if all the bits happen to be 1 (either because this exact key was inserted, or because other keys happened to set the same bits), the filter reports "maybe," which could be a false positive. More inserted keys means more bits set, which means a rising false-positive rate — that's the core tradeoff.
