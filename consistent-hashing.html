Consistent Hashing

Servers and keys share one ring instead of a plain hash % N. Add or remove a server and watch how little needs to be remapped, compared to a plain modulo scheme where almost everything would move.

How it works

Say you shard data across servers with plain hash(key) % number_of_servers. It works — until you add or remove a server. Then number_of_servers changes, so almost every key's target server changes too, forcing a massive remap of data.

Consistent hashing fixes this by placing both servers and keys on the same conceptual ring (hash values from 0 to some max, wrapped around like a clock). A key belongs to whichever server is the next one clockwise from its position on the ring.

Now add or remove a server: only the keys sitting between that server and the previous one on the ring need to move — everything else on the ring is completely unaffected. That's the entire benefit: remapping stays proportional to 1/number_of_servers of the data instead of nearly all of it.
