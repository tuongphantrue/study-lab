Topological Sort

Task dependencies as a graph: an arrow from A to B means A must finish first. Kahn's algorithm finds a valid execution order by repeatedly scheduling whatever has no unfinished prerequisites.

How it works

Topological sort only makes sense on a DAG (directed acyclic graph) — think task dependencies, where an edge A → B means "A must finish before B can start." The output is one valid order to do everything in, respecting every dependency.

This uses Kahn's algorithm: first count each node's in-degree (how many arrows point into it — how many prerequisites it has). Any node with in-degree 0 has no unfinished prerequisites, so it's ready to go now. Pick a ready node, add it to the output, then "remove" it — which means decrementing the in-degree of everything it points to. Some of those might now hit 0 and become ready themselves.

If the graph has a true cycle (A needs B, B needs A), some nodes never reach in-degree 0, and no valid order exists — Kahn's algorithm detects this simply by finishing with fewer nodes than the graph actually has.
